# Публикация panacea.gif

## Что куда публикуем

- Код проекта — в публичный репозиторий GitHub (например, `panacea-gif`).
- Работающее приложение — на Netlify; оно получит публичный HTTPS-адрес вида `https://<имя-сайта>.netlify.app`.

## Почему нужен Netlify

Веб-сборка FFmpeg использует `SharedArrayBuffer`. Для неё важны заголовки `Cross-Origin-Opener-Policy` и `Cross-Origin-Embedder-Policy`. Они уже заданы в файле `_headers`. Не удаляй этот файл при публикации.

## Быстрый запуск через Netlify

1. Распакуй ZIP.
2. Создай аккаунт/войди в Netlify.
3. Рекомендуемый вариант: создай GitHub-репозиторий и загрузи в его корень все файлы из этой папки, включая `_headers` и `netlify.toml`.
4. В Netlify выбери добавление нового проекта из существующего Git-репозитория, подключи `panacea-gif` и опубликуй.
5. Команда сборки не нужна; папка публикации — `.` (уже указана в `netlify.toml`).
6. После публикации открой выданный HTTPS-адрес, проверь загрузку движка FFmpeg и выполни реальную конвертацию маленького MP4.
7. Только после проверки добавь публичную ссылку в карточку `panacea.gif` на сайте-портфолио.

Можно сделать и разовую ручную публикацию статической папки через интерфейс Netlify, но привязка к GitHub удобнее для дальнейших обновлений: публикации будут обновляться после коммитов в репозиторий.

## Чек-лист после публикации

- [ ] Страница открывается по HTTPS.
- [ ] В DevTools Console выражение `crossOriginIsolated` возвращает `true`.
- [ ] При первом запуске FFmpeg загружается без ошибок.
- [ ] Небольшой MP4 конвертируется в GIF.
- [ ] Режим «Уложиться в размер» работает.
- [ ] Если ширина зафиксирована, приложение её сохраняет.
- [ ] В портфолио стоят две отдельные ссылки: «Открыть приложение» и «Исходный код».

## Важно

Видео обрабатывается в браузере, но приложение загружает FFmpeg с внешнего CDN при первом использовании. Для первого запуска нужен интернет. Успешную публикацию и работу на удалённом домене надо подтвердить тестированием — локальная работа сама по себе этого не гарантирует.
