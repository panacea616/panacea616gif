# panacea.gif — локальная версия без npm

Эта сборка не требует `npm install`, Vite или сторонних пакетов Node.js. Для запуска нужен только установленный Node.js.

## Запуск

1. Распакуй архив в отдельную папку.
2. Останови предыдущий panacea.gif в старом терминале сочетанием `Ctrl+C`, если он ещё работает.
3. Дважды нажми `START-LOCAL.bat` или открой терминал в этой папке и выполни `node server.js`.
4. Открой в браузере `http://localhost:5173`.
5. При первом использовании нужен интернет для загрузки FFmpeg.wasm с CDN. Если один CDN недоступен, приложение попробует второй.

## О текущей версии

- Режим «Уложиться в размер» стал отдельным сценарием: скрываются выбор профиля качества и ручные настройки ширины, FPS и палитры, чтобы не создавать конфликтующих сигналов.
- Карточка «Оценить размер» превращается в краткую сводку целевого лимита; предварительная оценка не показывается, так как в режиме лимита параметры подбираются во время конвертации.
- Основная кнопка меняется на «Подобрать GIF до X МБ» и отражает выбранный лимит.
- Автоподбор в режиме лимита начинает с максимальных поддерживаемых параметров (960 px, 24 FPS, 256 цветов), а затем подбирает лучший проверенный вариант, который укладывается в размер.
- При выключении режима лимита обычный интерфейс качества и кнопка «Оценить размер» возвращаются.

## Что изменено в версии 0.5

- Исправлено поведение кнопки «Оценить размер» сразу после конвертации: если файл уже создан и пользователь не менял параметры, отображается его фактический размер.
- Это устраняет путаницу в режиме «Уложиться в размер»: подбор может создать GIF на пониженных параметрах, а контролы по-прежнему показывают исходный желаемый профиль. Раньше оценка заново кодировала только исходные настройки и могла показать число выше лимита, хотя готовый GIF уже в него помещался.
- Если поменять видео, фрагмент, профиль, настройки или лимит, кеш точного результата сбрасывается и новая оценка рассчитывается заново.

## Что изменено в версии 0.4

- Переработан подбор под лимит размера: вместо четырёх грубых пресетов используется промежуточная лестница настроек, отсортированная по оценочному качеству.
- Каждый вариант реально кодируется и проверяется по размеру; выбирается первый подходящий в порядке качества, а не просто самый маленький GIF.
- В результате отображаются фактические настройки подобранного GIF и пояснение, уложился ли файл в лимит.
- Уточнено сообщение оценки размера, когда включён режим автоматического подбора.
- Временные GIF удаляются даже если конвертация завершается ошибкой, что снижает риск накопления данных в памяти FFmpeg.
- Логика подбора вынесена в `src/target-fit.mjs`, чтобы её было проще тестировать и менять отдельно от интерфейса.
- Добавлены автономные тесты логики подбора (без npm): `node --test tests/target-fit.test.mjs`.

## Что было изменено в версии 0.3

- Добавлены заголовки `Cross-Origin-Opener-Policy: same-origin` и `Cross-Origin-Embedder-Policy: require-corp`, необходимые для доступа к `SharedArrayBuffer`.
- Добавлена предварительная проверка изоляции браузера с понятной диагностикой, если заголовки не применились.
- Сохранён резервный CDN для FFmpeg core.
- Добавлен тайм-аут загрузки каждого источника и понятное сообщение, если движок недоступен.
- Добавлены сообщения о стадиях подготовки файла и прогресс конвертации.
- Оценка проверяет тестовый отрезок до 1 секунды, чтобы уменьшить время первичного теста.
- Для файлов больше 60 МБ показывается предупреждение о расходе памяти.

## Приватность

Исходное видео обрабатывается в браузере и не отправляется на наш сервер. При первом запуске загружаются только библиотеки обработки с CDN. Локальный сервер слушает только `127.0.0.1`.

## Если страница зависает

- Подожди, пока завершится загрузка движка; статус находится в панели прогресса.
- Если появится сообщение о тайм-ауте, обнови страницу и проверь интернет.
- Для первого теста используй небольшой MP4-файл и фрагмент 2–5 секунд.
- Остановить локальный сервер можно сочетанием `Ctrl+C` в его терминале.

Эта версия ещё прототип: после запуска нужно проверить загрузку FFmpeg и конвертацию на твоём компьютере и при необходимости исправить ошибки.

## Ускорение автоподбора (v0.10)

- Подбор под целевой размер больше не кодирует десятки вариантов последовательно. Сначала проверяется вариант максимального качества; если он уже в лимите, результат готов после одной конвертации.
- Если максимальный вариант не подходит, применяется бинарный поиск по упорядоченным настройкам качества, а затем проверяются ближайшие варианты около найденной границы. Это обычно сокращает число полных конвертаций примерно с 30–40 до 5–9, в зависимости от требуемого лимита и найденной границы.
- Каждый принятый вариант по-прежнему проверяется по реальному размеру готового GIF. Поскольку размер GIF зависит от содержимого и сжатие не строго монотонно, алгоритм является быстрым приближённым поиском качества, а не математической гарантией глобально лучшей комбинации. Если ни один проверенный вариант не помещается в лимит, показывается наименьший по фактическому размеру из проверенных результатов.
- Прогресс теперь показывает номер реальной попытки, потому что поиск проверяет кандидаты не по порядку.
- В памяти удерживаются только лучший подходящий результат и самый маленький проверенный GIF, а для остальных кандидатов сохраняются только измерения размера.

## Подбор размера v0.11

- Расширена сетка настроек: добавлено больше промежуточных сочетаний ширины, FPS и количества цветов, чтобы алгоритм не перескакивал через варианты, которые могут дать лучшее качество при том же лимите.
- После быстрого поиска границы алгоритм проверяет ближайшие 12 вариантов с более высоким оценочным качеством и не прекращает уточнение только потому, что один промежуточный GIF оказался больше лимита.
- Подбор по-прежнему проверяет фактический размер закодированного файла; он не пытается искусственно довести вес GIF до лимита, а ищет вариант с лучшими настройками среди проверенных.
- Прогресс обновлён под дополнительный этап уточнения.
- Добавлен тест на случай немонотонного размера GIF.
